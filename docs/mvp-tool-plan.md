# 다국어 웹 유틸리티 사이트 MVP 계획

> 작성일: 2026-09-18
> 목표: 전 세계 사용자가 즉시 쓸 수 있는 브라우저 기반 도구를 제공하고, 검색 유입과 재방문을 바탕으로 AdSense 수익을 검증한다.

## 1. 요구사항 요약

- 서버 없이 정적 HTML/CSS/JavaScript로 배포한다.
- 첫 출시부터 영어권을 포함한 다국어를 지원한다.
- 업무·개발·마케팅·디자인에서 반복적으로 쓰는 무료 도구를 제공한다.
- 도구 사용 데이터는 가능한 한 사용자의 브라우저 안에서만 처리한다.
- 광고는 도구의 실행·복사 버튼과 충분히 분리해, 이용 경험과 정책 준수를 함께 지킨다.

## 2. 제품 방향

### 제품명(가칭)

**Toolkitly** — 링크, 데이터, 시간, 디자인 작업을 즉시 끝내는 브라우저 도구 모음.

제품명은 확정 전 가칭이다. 도메인 확보 가능 여부와 상표 충돌 검토 후 교체한다.

### 핵심 사용자

| 사용자 | 자주 겪는 문제 | 우선 도구 |
| --- | --- | --- |
| 마케터·운영 담당자 | 캠페인 링크를 만들고 검수·공유해야 함 | UTM 생성기, URL 파서, QR 생성기 |
| 개발자·데이터 담당자 | JSON·인코딩·시간 데이터를 빠르게 확인해야 함 | JSON 도구, Base64, Timestamp |
| 디자이너·퍼블리셔 | 색상 접근성과 브랜드 색상을 확인해야 함 | Contrast checker, 색상 변환기 |
| 일반 사무 사용자 | 링크·텍스트·시간을 간단히 변환해야 함 | QR 생성기, 시간대 변환기, 텍스트 정리 |

### 차별화 원칙

1. 결과만 보여주는 입력창이 아니라, 오류 원인·예시·다음 행동을 안내한다.
2. 서로 관련 있는 도구를 연결한다. 예: UTM 생성 → URL 검수 → QR 생성.
3. 입력 데이터는 기본적으로 외부 서버에 전송하지 않는다.
4. 번역만 바꾼 대량 페이지를 만들지 않고, 언어별 예시·FAQ·용어를 자연스럽게 제공한다.

### 출시 후 우선 검증: P1

P0의 실제 유입·검색어·이탈률을 확인한 뒤 추가한다.

- 정규식 테스트기 및 정규식 치트시트
- Open Graph / 소셜 공유 미리보기
- Cron 표현식 해석기
- 텍스트 비교기(diff), 줄바꿈·공백 정리기
- 비밀번호 강도 검사기(입력값 브라우저 내 처리)
- Lorem ipsum / 샘플 JSON 생성기

### 이번 MVP에서 제외

- PDF·이미지 업로드 및 변환: 처리 비용, 보안·저작권·저장 정책이 필요함
- AI 생성·번역: 외부 API 비용과 품질·악용 대응이 필요함
- 환율·세금·법률·의료 계산: 최신 외부 데이터와 정확성 책임이 필요함
- 로그인, 즐겨찾기 동기화, 팀 협업, 결제: 서버·개인정보·운영 부담이 추가됨
- 자체 URL 단축 서비스: 악성 링크 방지와 신고·차단 운영이 필요함

## 4. 공통 페이지와 사용자 흐름

### 공통 구성

모든 도구 페이지는 다음 순서를 따른다.

1. 제목과 한 줄 가치 제안
2. 입력 영역과 즉시 실행 버튼
3. 결과·오류·복사·다운로드 영역
4. 짧은 사용 예시와 FAQ
5. 관련 도구 2~4개
6. 광고 영역(입력·결과·주요 버튼과 시각적으로 분리)

### 대표 흐름: 마케팅 링크

```text
UTM 링크 생성
  → URL 파서로 파라미터 검수
  → QR 코드 생성
  → 이미지 또는 링크 복사·다운로드
```

### 대표 흐름: API 데이터

```text
JSON 포매터·검증
  → JSON 비교 또는 CSV/YAML 변환
  → 복사·다운로드
```

## 5. 기술·배포 설계

### 정적 우선 아키텍처

```text
브라우저
  ├─ 정적 HTML / CSS / JavaScript
  ├─ 로컬 변환·검증·파일 생성
  ├─ Analytics / Search Console 측정
  └─ AdSense 광고 태그

CDN 정적 호스팅
  └─ 다국어 페이지, 이미지, sitemap, robots.txt
```

- 프레임워크는 SEO와 정적 생성에 유리한 **Next.js static export** 또는 **Astro** 중 하나를 선택한다.
- 도구의 변환 로직은 재사용 가능한 순수 함수 모듈로 분리한다.
- 외부 API 호출 없이 동작하는 기능을 우선한다.
- 파일은 브라우저에서 생성해 다운로드한다. 입력값과 결과를 기본적으로 저장하거나 전송하지 않는다.
- 정적 호스팅은 Cloudflare Pages, Vercel, Netlify 중 비용·배포 흐름을 비교해 하나를 선택한다.

## 5-1. UI 디자인 기준

### 참조와 적용 범위

- 참조 UI: [DevToolsHub](https://devtools-hub-beryl.vercel.app/)
- 참고할 요소: 다크 작업 공간, 상단 도구 검색, 낮은 대비의 카드 그리드, 작은 파란색 도구 아이콘, 높은 정보 밀도.
- 복제하지 않을 요소: 사이트 이름·로고·카피·소스 코드·GitHub 링크·즐겨찾기 기능.

### 확정된 화면 원칙

- 전체 분위기는 흑청색 기반의 **industrial / developer utility** 스타일로 한다.
- 상단 고정 헤더에는 로고, 전체 도구 검색, 언어 선택, 테마 전환만 둔다. GitHub 링크는 넣지 않는다.
- 홈 화면은 큰 마케팅 히어로 대신 짧은 제목과 설명, 카테고리 필터, 3열 도구 카드로 시작한다.
- 도구 카드는 아이콘, 이름, 한 줄 설명, 카테고리만 표시한다. 즐겨찾기 아이콘과 계정 기능은 넣지 않는다.
- 도구 상세 화면은 데스크톱에서 입력과 결과를 좌우로 배치하고, 모바일에서는 세로로 쌓는다.
- 입력값·결과값·단축키·상태 메타데이터에는 monospace 글꼴을 사용한다.
- 광고는 자동 광고를 사용한다. 수동 광고 슬롯을 만들지 않으며, 자동 삽입이 실행·복사·다운로드 버튼과 혼동되지 않도록 도구 컨테이너의 여백을 확보한다.

### 초기 디자인 토큰

| 영역 | 값 | 용도 |
| --- | --- | --- |
| 페이지 배경 | `#0B0E14` | 전체 배경 |
| 표면 | `#121722` | 카드·패널 |
| 표면 강조 | `#171E2B` | 입력·hover 상태 |
| 경계선 | `#252D3D` | 카드·구분선 |
| 본문 | `#E6EDF7` | 제목·주요 텍스트 |
| 보조 본문 | `#94A3B8` | 설명·메타 정보 |
| 강조 | `#3B82F6` | 주요 버튼·아이콘·focus |
| 성공 / 오류 | `#34D399` / `#FB7185` | 검증 결과 |
| 본문 글꼴 | Geist | 메뉴·본문·버튼 |

### 접근성·반응형 기준

- 본문/배경 대비는 최소 WCAG AA를 만족한다.
- 키보드 focus 상태는 강조색 외곽선으로 명확히 표시한다.
- 카드 그리드는 넓은 화면 3열, 태블릿 2열, 모바일 1열로 전환한다.
- 색상만으로 성공·오류를 구분하지 않고 텍스트와 아이콘을 함께 표시한다.

## 6. 다국어와 검색 유입 설계

### 초기 지원 언어

| 우선순위 | 언어 | URL 예시 |
| --- | --- | --- |
| P0 | 영어 | `/en/tools/utm-builder` |
| P0 | 한국어 | `/ko/tools/utm-builder` |
| P1 | 일본어 | `/ja/tools/utm-builder` |
| P1 | 스페인어 | `/es/tools/utm-builder` |
| P1 | 브라질 포르투갈어 | `/pt-br/tools/utm-builder` |

- 언어별 canonical URL, `hreflang`, 페이지 제목, 메타 설명, Open Graph 정보를 제공한다.
- 각 언어의 설명·예시·FAQ는 해당 사용자가 실제로 검색할 표현을 기준으로 별도 작성한다.
- 도구 목록·카테고리·관련 도구 링크를 제공해 검색 엔진과 사용자가 구조를 이해하게 한다.
- `sitemap.xml`, `robots.txt`, 404 페이지, 개인정보처리방침, 이용약관, 연락처 페이지를 출시 전에 포함한다.

## 7. 광고 및 정책 준비

- 초기 수익 모델은 AdSense로 한정한다.
- 광고는 데스크톱에서 본문 상단 또는 결과 아래, 모바일에서 결과·관련 도구 사이에 배치한다.
- 실행·복사·다운로드 버튼 근처에는 광고를 두지 않아 오클릭 위험을 줄인다.
- 개인정보처리방침, 쿠키/광고 기술 고지, EEA·영국·스위스 대상 동의 관리 요건을 배포 전에 검토한다.
- AdSense 승인 전에도 광고 위치는 빈 placeholder로 디자인하고, 실제 광고 코드는 승인 후 활성화한다.
- 광고 노출을 늘리기 위해 불필요한 페이지 전환, 강제 스크롤, 결과 잠금, 클릭 유도 문구를 사용하지 않는다.

## 8. 성공 조건과 측정 지표

### 출시 완료 기준

- P0 도구 12개가 모바일·데스크톱에서 동작한다.
- 각 도구가 영어·한국어로 제공되고, 언어별 제목·설명·FAQ·`hreflang`을 갖는다.
- 핵심 변환은 네트워크 연결 없이도 브라우저에서 동작한다.
- 입력 오류가 발생했을 때 원인과 수정 방향을 안내한다.
- 개인정보처리방침, 이용약관, 문의, sitemap, robots.txt가 배포되어 있다.
- Lighthouse 기준 접근성·SEO·성능의 치명적 오류가 없다.

## 9. 단계별 실행 계획

### 1) 정보 구조와 브랜드 기반 확정

- **목표:** 도구 목록·카테고리·URL 규칙·다국어 구조를 고정한다.
- **변경 대상:** 사이트맵, 라우트 명세, 번역 키 구조, 디자인 토큰.
- **이유:** 도구를 추가해도 URL과 내부 링크가 흔들리지 않게 한다.
- **기대 효과:** 중복 구현과 SEO 구조 변경을 줄인다.
- **리스크:** 지나친 초기 카테고리 세분화.
- **검증 방법:** 모든 P0 도구가 한 개의 주 카테고리와 관련 도구 경로를 갖는지 검토.
- **산출물:** 사이트맵 및 라우트/번역 명세.

### 2) 공통 도구 셸과 정적 배포 기반 구현

- **목표:** 모든 도구가 같은 사용 경험과 메타데이터 체계를 사용하게 한다.
- **변경 대상:** 레이아웃, 입력/결과/오류 컴포넌트, 복사·다운로드 유틸리티, 정적 호스팅 설정.
- **이유:** 도구별 UI·정책·SEO 누락을 방지한다.
- **기대 효과:** 새 도구 추가 속도와 품질이 올라간다.
- **리스크:** 공통 컴포넌트가 특정 도구 제약을 과도하게 강제할 수 있음.
- **검증 방법:** 샘플 도구 2개에서 모바일·키보드·복사 동작을 확인.
- **산출물:** 공통 도구 페이지 템플릿과 프리뷰 배포.

### 3) 링크·마케팅 도구군 출시

- **목표:** UTM, URL 파서/인코더, QR 생성기의 완성된 흐름을 제공한다.
- **변경 대상:** 링크 관련 4개 도구와 테스트 케이스.
- **이유:** 가장 넓은 업무 사용자와 상업적 검색 의도를 우선 확보한다.
- **기대 효과:** 관련 도구 간 이동과 공유가 발생한다.
- **리스크:** URL 인코딩 방식·UTM 예약문자 처리 오류.
- **검증 방법:** 공백, 한글/이모지, 중복 query key, fragment가 포함된 URL의 라운드트립 테스트.
- **산출물:** 링크·마케팅 도구군과 영문/한글 콘텐츠.

### 4) 데이터·시간·디자인 도구군 출시

- **목표:** JSON, Base64, 시간, 색상 도구를 추가해 재방문 이유를 넓힌다.
- **변경 대상:** P0의 나머지 도구, 순수 변환 모듈, 단위 테스트.
- **이유:** 개발·디자인 업무의 반복 수요를 포괄한다.
- **기대 효과:** 검색 진입점과 사이트 내 사용 시나리오가 증가한다.
- **리스크:** JSON 중첩 구조의 CSV 변환, DST가 적용되는 시간대 계산, 대비 비율 계산 오류.
- **검증 방법:** 고정 fixture, DST 전환일, WCAG 대표 색상 조합을 자동 테스트.
- **산출물:** P0 도구 12개와 회귀 테스트.

### 5) 다국어·SEO·정책 및 측정 준비

- **목표:** 색인과 광고 심사를 받을 수 있는 사이트 운영 기반을 완성한다.
- **변경 대상:** 번역 콘텐츠, `hreflang`, sitemap, 정책 페이지, Analytics/Search Console, 동의 관리.
- **이유:** 영어권 검색 유입과 광고 운영에 필요한 신뢰·측정 기반을 갖춘다.
- **기대 효과:** 언어별 유입을 분리해 개선하고, 정책 리스크를 낮춘다.
- **리스크:** 기계 번역형 얇은 콘텐츠, 누락된 동의/개인정보 고지.
- **검증 방법:** 각 언어 URL의 메타데이터·상호 `hreflang`·sitemap, 정책 페이지 연결, 이벤트 수집을 확인.
- **산출물:** 배포 후보 사이트와 운영 체크리스트.

### 6) 제한 공개와 90일 개선 루프

- **목표:** 실제 검색어와 행동 데이터를 근거로 P1을 결정한다.
- **변경 대상:** 이벤트 대시보드, 도구별 설명/FAQ, 내부 링크, P1 백로그.
- **이유:** 추측으로 도구 수만 늘리는 것을 막는다.
- **기대 효과:** 유입·실행·수익이 확인된 영역에만 개발 자원을 집중한다.
- **리스크:** 짧은 기간의 광고 수익만 보고 장기 검색 가치를 잘못 판단할 수 있음.
- **검증 방법:** 30/60/90일 단위로 Search Console·Analytics·AdSense 지표를 함께 검토.
- **산출물:** P1 우선순위 결정 문서.

## 10. 출시 전 체크리스트

- [ ] 모바일·데스크톱·키보드만으로 모든 P0 도구를 실행할 수 있다.
- [ ] 오류 상태가 사용자 언어로 이해 가능하게 표시된다.
- [ ] 입력값이 기본적으로 서버에 저장·전송되지 않는다.
- [ ] 복사, 다운로드, 새로고침 후 상태 처리 방식이 일관적이다.
- [ ] 다국어 canonical/hreflang/sitemap이 상호 일치한다.
- [ ] 개인정보처리방침·이용약관·문의·쿠키/광고 고지가 연결되어 있다.
- [ ] 광고가 주요 행동 요소와 분리되어 있고, 클릭 유도 문구가 없다.
- [ ] Analytics 이벤트와 Search Console 속성이 설정되어 있다.
- [ ] Lighthouse 및 대표 브라우저 수동 점검을 마쳤다.
